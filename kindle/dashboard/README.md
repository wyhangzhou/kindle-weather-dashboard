# 30 分钟天气模式

这是一套手动启动的 KUAL 扩展，适用于本项目已经越狱、完成 KUAL 兼容签名处理及 HTTPS 工具安装的 Kindle 4 Black / 固件 4.1.2。保留原生阅读框架，更新时开 Wi-Fi，显示后关 Wi-Fi 并请求 `mem` 休眠，墨水屏保留天气图。

## 使用

KUAL → **Weather**：

- **Start weather (30 min)**：持续运行，成功更新后约 30 分钟唤醒再下载。
- **Check one 30-min cycle**：两次下载，中间一次完整 30 分钟休眠，然后自动恢复阅读。任何一次下载失败都记录为试运行失败。
- **Stop weather / Read**：停止后台进程，恢复保存的原闹钟及 Wi-Fi/屏保状态，返回 Home。

启动准备图出现后 15 秒内拔 USB，横放设备、实体按键位于左边。仍在充电则本次启动取消。唤醒状态按 Home 退出；真正休眠时短按电源键会提前唤醒并退出，必要时再按 Home。插回 USB 导致提前唤醒时也会退出，便于维护。发生提前唤醒就保守地返回阅读模式，日志记录实际原因；不把它当作正常定时更新。

试运行约半小时后自动回 Home。如果线上图片未变，不重复刷新墨水屏；以日志确认第二次下载。30 分钟完整周期及长期运行仍待本机试运行，不能由短周期通过推算为已验证。

## 构建与安装

在仓库根目录运行：

```sh
.venv/bin/python kindle/dashboard/render_screens.py
python3 kindle/build_bundle.py
```

将生成的 `build/kindle-weather/` 放到 `/mnt/us/extensions/kindle-weather/` 并保留 `.sh` 执行权限，重新打开 KUAL。构建器复用 `kindle/weather-test/` 中实际下载、严格校验、按键监听和 RTC 恢复四个模块，生成逐文件 SHA-256 清单；不包含 SSH 私钥、GitHub 凭据、系统组件或字体。

前提是用户目录已有 `/mnt/us/kindle-weather/runtime/xh` 和独立 CA `/mnt/us/kindle-weather/tls/cacert.pem`。下载地址固定为本项目的 HTTPS Pages；城市、温度单位及画面方向仍由云端 `config.toml` 控制。

`run.sh --check` 只读检查。`run.sh --self-check` 短暂关 Wi-Fi 并合成 Home 验证原值恢复，不画图、不设置未来闹钟、不休眠。复制读回、语法和这些自检通过后，仍需真正运行 30 分钟并读取日志。

## 失败、退出与记录

请求失败、图片错误或天气过期时，保留上次有效缓存和其原始时间标记。连续失败按 5、10、30 分钟退避重试；缓存内容相同时不额外刷屏。没有可用缓存则退出回 Home，不显示伪造天气。开始要求电量至少 20%，运行中低于 15% 则恢复阅读并停止。

原 Wi-Fi、无线开关、屏保值和本次启动标识保存在 `/mnt/us/kindle-weather/state/dashboard.props`；闹钟保存及所有权在 `alarm-dashboard*` 文件。成功恢复后清除状态文件。硬件闹钟恢复沿用已验证的两个 RTC 报警寄存器整值读改写，禁止中断掩码或时钟写入。其他服务替换了闹钟时拒绝覆盖，记录错误并保留状态供检查。

`stop.sh` 只向命令行匹配此扩展的 PID 发信号；不强杀，也不终止原生阅读进程。若后台已经退出但保留了状态，尝试恢复；跨重启保留新系统的默认电源/无线状态。异常重启和故障恢复的完整路径仍待测试，未声称已经通过。恢复失败时先检查日志和保留的状态文件，避免盲目再次启动。

日志为 `/mnt/us/kindle-weather/logs/dashboard.log`，约 128 KiB 滚动并保留一份旧日志。它记录下载、缓存使用、显示、Wi-Fi 关闭、计划和实际休眠时长、退出恢复结果，不记录 Wi-Fi 密码或完整设备标识。

没有安装任何开机启动任务。GitHub 的计划任务不是精确定时服务；目前构建和部署、保活手动执行及设备下载通过，首次真实 cron 触发仍待观察。云端停止更新时设备保留旧图，通过图上的数据时间可辨别陈旧内容。
